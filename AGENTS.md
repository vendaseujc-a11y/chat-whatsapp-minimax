# OpenCode Project Configuration (`AGENTS.md`)

This file provides system context, build commands, and coding standards for OpenCode AI coding agents working on the **Chat Backend - MiniMax M2 via OpenRouter** project.

## Project Context
A Node.js Express backend and single-page HTML frontend that integrates MiniMax M2 via OpenRouter to act as an automated e-commerce WhatsApp assistant for the "VouComprarFácil" store, selling sports supplements.

---

## Technical Stack & Architecture

### Backend (Node.js & Express)
*   **Framework:** Express.js (`src/index.js`)
*   **Database:** SQLite via `sql.js` in-memory database with SQLite file loading/persistence (`src/config/database.js`).
*   **AI Integration:** OpenRouter API (`https://openrouter.ai/api/v1/chat/completions`) using the `openrouter/free` model (MiniMax M2 configuration).
*   **Environment Variables:** Configured using `dotenv` for reading `OPENROUTER_API_KEY` and server parameters (`PORT`, `HOST`).

### Frontend (Single Page App)
*   **Interface:** `index.html` (an interactive WhatsApp-like web interface to chat with the AI assistant).

| Task | Command | Description |
| :--- | :--- | :--- |
| **Install Dependencies** | `npm install` | Installs the project dependencies. |

## Development Guidelines & Rules

### 1. Strict Assistant Rules (AI Prompt Consistency)
When modifying the system prompt or backend chat logic in `src/index.js`:
*   **No Prices in Chat:** The assistant MUST NEVER output specific prices. Instead, it must offer the product catalogue and direct the customer to a WhatsApp human partner using the WhatsApp partner link.
*   **Enthusiastic Tone:** The assistant must use emojis (✨🛍️💪⚡) and explain supplement benefits in detail.
*   **WhatsApp Partner Redirect:** Ensure that when users want to buy or ask for pricing, the assistant responds with the WhatsApp partner link generated by `generateWhatsAppLink()`.

### 2. Code Quality & Standards
*   **Style:** Plain JavaScript (ES6+ Node.js) with CommonJS (`require`) module syntax.
*   **Routing:** Maintain RESTful APIs with clean error Handling (especially handling API 429 Limit errors gracefully).
*   **Database:** Utilize functions in `src/config/database.js` for saving/retrieving session context messages.
